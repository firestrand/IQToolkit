# Hardness report: nullable-column continuity verification

The accepted SQLite string-column coverage comparison now has a reusable implementation in [NullableColumnContinuity](../eng/FinalVerification/NullableColumnContinuity.cs), called through the final verifier's `nullable-continuity-control` operation. Its private Release build and both controls passed independent Oracle review. This is a prerequisite for final evidence integration; it does not select a new active descriptor or qualify current-final readiness.

The owner-selected [Cross-Platform .NET Engineering Standard 1.1.0-draft.1](standards/source/Cross-Platform-DotNet-Engineering-Standard-1.1.0-draft.1.md) governs the work, especially warning, coverage, private-storage and process controls. Development Plan Creation Guide 2.7 and the autonomous execution guide govern protecting evidence, ownership and review. [The prospective GOTCHA contract](../artifacts/nullable-continuity/contract.json) was approved before the source lease and execution. Generated data authorization remains absent; both controls use authentic retained descriptors, coverage reports, suites and compiled symbols.

## Failure handling, storage and concurrency

Prospective review corrected missing source-copy wiring, five omitted native log/source seals, preparation-failure disposition, runner disposition authorization and preparation-snapshot authentication before dispatch. The original source-review versions are retained. There were no failed native attempts or artifact repairs in this tooling slice. The earlier nullable acquisition/qualification repair count remains two of three; no old consumer or cache-seed budget is reset.

The packet measured 1,376 original/snapshot input pairs. Its complete conservative allocation was 820,078,504 bytes, below the 2 GiB limit; actual terminal owned storage was 314,234,077 bytes. The packet completed in 5.316 seconds; terminal preservation took 0.321 seconds. Preparation snapshots, source/index identities and all 336 ordinary binaries remained unchanged. All five process sessions were empty before retirement; the original private parent is absent and all 60 retained files match the authenticated retirement inventory. Source/project/binary assets are inactive snapshots. No shared build, database or package-feed mutation occurred.

Private paths and metadata remain local evidence; no credentials or application records were acquired. JSON duplicate-property checks, XML DTD prohibition, bounded capture and exact hash/context checks remain in place.

## Remaining integration

Current-final adoption still requires authenticated historical replay, contextual aliases for each expected historical identity, current descriptor selection, explicit registration of the two canonical facts and four-method nullable fact, reviewed cache/source compatibility, and fresh checked consumer locks/feed and producer evidence. The existing 34 ledger rows and historical 33-fact/87-method binding remain unchanged. The new coordinator and wrapper source identities must be included in that future contract rather than treated as historical byte equality.

The profile retains its draft 0.106 documentation pins; draft 0.107 records this later checkpoint without promoting them. Full-project coverage, coverage targets, mandatory broad fact obligations, optimized cache-seed qualification, unanswered owner decisions and the wider roadmap remain open.
